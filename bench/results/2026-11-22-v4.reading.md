## Reading

Written by hand from the tables above. Every setup ran 3 times per task, so one run is a third of a cell.

**Claim 1, context: a commander's parent stays flat while a subagent parent grows. It did not hold.** Every parent
grew by about 2k tokens per piece, commander or not. On L8 the peaks were A4 42k, D4 39k, D0 44k (medians; D4's range
36-43k covers A4's 42-43k). On L5 they were A4 35k, D4 37k, D0 34k. The per-call series climb the same way in all
three: about 25k at the first call, then 1-2k for each report read. A report costs the same whether a subagent or a
spawned session writes it. The commander only reads it in a different envelope.

v2 and v3 showed a flat commander for another reason. A headless `claude -p` commander ends when its turn does,
and yap's wake only reaches a session idle in a pane. So those commanders dispatched, exited, and never read one
report: 2 parent calls each, in v3 and in this bench's first dry run (`2026-11-22-v4-dry1.md`). v4's harness stands
in for the pane: the commander's stdin stays open, and when a spawn ends while it is idle, the runner sends yap's own
wake line (`yap: a message from session @…`). Its prompt hook then hands it the waiting reports, as in a pane. That
is what was measured here.

**Claim 2, hooks: yap's hooks help workers sharing one tree. Not shown at n=3.** D0 (hooks off) did as well as D4
on every column measured:

- Pass: L8 18 of 24 features for both. L5 D0 14 of 15, D4 12 of 15. The whole L5 gap is feature 56.1: D0 passed
  it in 2 runs, D4 in none. That is two runs, and it favours the setup without the hooks.
- Collisions: about one file edited by two workers per run in both; 1 clobbered run of 3 on L8 in each, none on L5.
- Time and cost: D0 was cheaper (L8 $0.92 against $1.12; L5 $0.66 against $0.81) and no slower. D4's workers read
  more tokens (L8 2,753k against 2,398k).

D4's workers got one peer warning each, at start-up, and no other. Whether any worker acted on one was not traced.
The clobber counter sees only Edit, MultiEdit and Write. A file rewritten through Bash would not show.

**Pass rates tie across all three setups.** Every L8 run passed the same 6 of 8 features. 26.3 (TestVersionSelector,
TestRoleBasedSelector) and 27.3 failed in all 9 runs of every setup, though the gold union passes both. 27.3 has
now failed every run since v1. On L5 every run passed 56.2, 56.4 and 56.5. The differences are 56.1 (A4 1, D4 0,
D0 2 of 3) and 56.3 (A4 2 of 3).

The ceiling first read L5 4 of 5: the gold union failed 56.1 once, on `TestMethodNotAllowed/Unregistered_Method`.
Run again 5 times, it passed every time, so that subtest is flaky on the gold patch (1 failure in 6) and the ceiling
is 5 of 5 (`2026-11-22-v4-gold.json`). The runs' own 56.1 results are not flaky: each L5 run's final patch, scored 5
more times on 56.1, gave the same answer every time.

**Time is mixed.** On L8 D4 was fastest (175 s median against A4 211 s; quartiles 165-208 s and 207-224 s barely
overlap). On L5 A4 was fastest (120 s against D4 166 s and D0 136 s). Each spawned worker pays its start-up and
reads its own context, so D costs more tokens: on L8, D4 2,753k against A4 1,962k.

**Found on the way: the report names a worker differently from the spawn.** `yap spawn` answers
`started @ed68c61d`, but the report arrives `from session @mux-3`, the worker's name taken from its first file. One
woken commander in the full run (L8-r2-D4) and the second dry run's D4 said so ("isn't one of my eight worker IDs")
and could not match reports to workers. The others took the reports as they came. The fix belongs in yap: name the
spawn id in the report's sender.
